# 14 – AMC Data Migration Plan (18.0.1.0.0 → 18.0.1.1.0)

## 1. Affected data

| Model | Change | Mapping |
|---|---|---|
| amc.contract | new columns (computed `contract_months`, visit statistics, lifecycle fields) | `contract_months` = plan duration at upgrade; statistics computed from visits |
| amc.plan | new columns `visit_planning_mode` (alert), `grace_days` (0), `auto_mark_missed` (False), `renewal_notice_days` (30) | defaults |
| amc.contract.visit, amc.billing.line | new tables | generated by `post-migrate.py` |
| ir.sequence / ir.cron / ir.actions.report / views / menus | new records | module data |

## 2. Post-migration script (`migrations/18.0.1.1.0/post-migrate.py`)

* **Awaiting Payment** contracts: billing schedule from the confirmed SO lines; periods already
  delivered on the SO lines are marked *released*; if none is released, period 1 is released so that
  the first invoice can be created (its payment activates the contract).
* **Active** contracts: billing schedule (as above) + entitlements from the existing start date +
  billing dates **without release** (the next daily scheduler run releases due periods).
* Draft / Quotation / Cancelled contracts: nothing to migrate (generated by the normal flow).
* Re-runnable: contracts with an existing schedule (and visits when Active) are skipped; each
  contract in its own savepoint. No deletion, no state / price change, no invoice.

## 3. Preconditions and backup

1. Stop the Odoo service (or PyCharm run configuration) of the target database.
2. Back up the database (`pg_dump -Fc`) and the filestore.
3. Restore the backup to a trial database and run the upgrade there first (§5).

## 4. Validation queries

```sql
-- contract values must be identical before / after
SELECT id, name, state, price, start_date, end_date, sale_order_id, price_state, formula_id
FROM amc_contract ORDER BY id;
-- entitlements of active contracts = visit_count x quantity (+ free services)
SELECT c.name, v.visit_type, count(*) FROM amc_contract_visit v JOIN amc_contract c
  ON c.id = v.contract_id GROUP BY 1, 2 ORDER BY 1, 2;
-- billing periods = SO line quantities; released = delivered
SELECT contract_id, count(*), count(*) FILTER (WHERE state = 'released') FROM amc_billing_line
GROUP BY 1;
SELECT order_id, product_uom_qty, qty_delivered FROM sale_order_line
WHERE order_id IN (SELECT sale_order_id FROM amc_contract WHERE sale_order_id IS NOT NULL);
```

## 5. Executed verification (2026-11-06)

Disposable database `amc_upg`: `amc_management` **1.0.0 installed from the original zip copy**
(no `amc_billing_line` / `amc_contract_visit` tables), seeded with the 1.0.0 code (Draft, Quotation,
Active 10 units quarterly, Awaiting Payment), then `-u amc_management` with 1.1.0:

* contract values identical before / after (diff empty);
* Active contract: 30 preventive + 10 free entitlements, 4 billing periods dated, none released;
* Awaiting Payment contract: 4 periods, period 1 released (`qty_delivered` 0 → 1);
* re-run of the migration function: counts unchanged (idempotent);
* module version 18.0.1.1.0.

## 6. Rollback

Restore the pre-upgrade dump and filestore; redeploy the 1.0.0 code. (Downgrading the module in
place is not supported by Odoo.)
